# 环境适配说明

> 目标环境不是"现代 Python"，而是海龟编辑器内置的老版本解释器。
> 本文记录**实测事实**、**已经踩过的坑**、**还没踩但一定会踩的坑**，以及**预防机制落在哪个文件**。
> 最后更新：2026-11-23　|　配套脚本：`tools/envcheck.py`

---

## 0. 一句话结论

海龟编辑器内置 **Python 3.6.5 + pygame 1.9.6（SDL 1.2）**，比常见的 pygame 2.x 少一大截 API；Windows 上 `open()` 默认编码还是 **GBK**。这两点决定了：**不能直接套用网上的 pygame 教程代码**，所有图形绘制和文件读写都必须经过项目自己的两个中间层。

## 1. 环境事实（2026-11-23 实测）

| 项 | 值 | 影响 |
|---|---|---|
| 编辑器 | `D:\tools\Pyblock\TurtleEditor.exe`（Electron 应用） | 界面是网页外壳，真正的代码在它内置的 Python 里跑 |
| 解释器 | `D:\tools\Pyblock\resources\app\Python-win64\python.exe` | 64 位，MSC v.1900 |
| Python | **3.6.5** | 无 walrus、无 f-string `=`、无标准库 `dataclasses` |
| pygame | **1.9.6** | 无 `border_radius`、无 `clipline`、无 `SCALED` |
| SDL | 1.2（驱动 `windib`） | 没有 `WINDOWFOCUSLOST` 等事件，只有 `ACTIVEEVENT` |
| 默认编码 | **cp936（GBK）** | `open()` 读 UTF-8 中文直接抛 `UnicodeDecodeError` |
| 第三方库 | `numpy`、`PIL`、`pygame.gfxdraw`、`pygame.surfarray` 可用 | 有余量，但**不写进依赖**，避免换机器就崩 |
| `dataclasses` | 装了 backport | 能用，但**不保证别人机器也有**，禁用 |
| 中文字体 | `simkai / msyh / simhei / simsun / Deng / stkaiti` 全部可用 | 楷体渲染正常 |
| 音频 | 默认真实设备 44100/-16/2；无设备时报 `error: No available audio device` | 必须 try/except 降级 |

**性能基线**（960×540，本机实测）：

| 操作 | 耗时 | 结论 |
|---|---|---|
| 40 个精灵 + 全屏地砖单帧 | 1.2 ms | 60fps 预算 16.7ms，余量充足 |
| `display.flip()` | 0.84 ms | 可接受 |
| `screen.fill()` | 0.46 ms | 正常 |
| `font.render()` 一段文字 | 0.021 ms | **不需要缓存文字** |
| `compat.panel()`（2× 超采样） | 0.75–0.95 ms | **超过 0.5ms，多面板必须缓存** |
| `smoothscale` 2000×800 → 960×540 | **7.68 ms** | **绝对不能每帧调用** |
| `scale`（非平滑）同尺寸 | 1.26 ms | 缩放必须移到加载期 |

## 2. 已经踩过的 5 个坑（已修复，不要再犯）

### P1. 显示面是 8 位调色板 → 文字变实心黑块

- **现象**：第一版截图里中文全是一整条黑色矩形，主角、金币、篝火全部消失。
- **证据**：`pygame.display.set_mode((960,540))` 后 `get_bitsize()` 返回 **8**（仅无头驱动；真实窗口是 32 位）。
- **根因**：pygame 1.9.6 + `SDL_VIDEODRIVER=dummy` 默认给 8 位调色板表面，颜色被量化、per-pixel alpha 丢失。
- **方案**：`compat.make_display()` 显式传 `depth=32`，**禁止**在业务代码里直接调 `pygame.display.set_mode`。

### P2. 没有 `draw.rect(border_radius=)`

- **现象**：`TypeError: rect() takes no keyword arguments`。
- **方案**：`compat.rounded_rect()` / `compat.panel()`，用多边形路径画圆角。

### P3. 没有 `Rect.clipline()` / `math.dist()` / `pygame.SCALED`

- **方案**：`compat.clip_line()`、`compat.dist()`；窗口固定 960×540，不做 SCALED 缩放。

### P4. `gfxdraw.aapolygon` 漏画整条底边

- **现象**：圆角矩形只画上边和半截左右边，底边完全消失。放大截图确认过。
- **根因**：pygame 1.9.6 的 SDL_gfx 在 28 点闭合路径上处理异常。
- **方案**：描边改用 `pygame.draw.lines(..., closed=True, width=w)`（实测四边完整闭合）；填充用 `draw.polygon`；需要抗锯齿时 2× 超采样再 `smoothscale`。

### P5. `pygame.font.match_font` / `SysFont` 直接崩

- **现象**：`TypeError: expected str, bytes or os.PathLike object, not int`（枚举注册表字体时）。
- **方案**：按文件名探测 `%WINDIR%\Fonts\simkai.ttf` 等，见 `config.FONT_DIRS` + `config.FONT_CANDIDATES`。

## 3. 还没踩、但一定会踩的 6 个坑（预防方案已就位）

### Q1. 裸 `open()` 读 UTF-8 必崩 ★最高危

```python
# 实测报错
UnicodeDecodeError: 'gbk' codec can't decode byte 0xac in position 2: illegal multibyte sequence
```

关卡文件、存档、告示牌文案全是 UTF-8。**只要有一处忘了传 encoding，游戏在 M3 加载第一关时就会崩**。

- **方案**：项目内**禁止**用 `open()` 读写文本，统一走 `io_utils`：
  - `read_text(path)` / `read_lines(path)` — 自动 UTF-8 + 去 BOM
  - `write_text(path, s)`
  - `read_json(path, default)` — 损坏时返回默认值，**存档不能因为写坏就进不去游戏**
  - `write_json(path, data)` — 临时文件 + `os.replace` 原子写
- 二进制读写（`open(path, 'rb')`）不受影响。

### Q2. 没有声卡时 `mixer.init()` 抛异常

- **证据**：`error: No available audio device`。
- **方案**：音频初始化必须 try/except，失败则置 `audio_enabled = False`，**游戏照常运行**，只是没声音。所有播放调用前判空。

### Q3. SDL 1.2 没有焦点事件，且相关常量都缺失

- **证据**：`WINDOWFOCUSLOST / WINDOWFOCUSGAINED / APPINPUTFOCUS / APPMOUSEFOCUS / APPACTIVE` **全部不存在**；只有 `ACTIVEEVENT`。
- **风险**：Alt+Tab 切出去后，SDL 1.2 的 `key.get_pressed()` 可能**卡住按键**，玩家回来时角色一直往一个方向跑。
- **方案**：
  ```python
  SDL_APPINPUTFOCUS = 2   # pygame 1.9.6 没暴露，按 SDL 1.2 定义手写
  if event.type == pygame.ACTIVEEVENT and (event.state & SDL_APPINPUTFOCUS):
      if not event.gain:
          input.reset()      # 清空按键快照
          pause()
  ```

### Q4. 缩放大图 7.68ms、画面板 0.75ms —— 很容易把帧预算吃光

- **方案**：
  - 所有 `smoothscale` 只在**加载期**做一次，结果缓存进字典；
  - UI 面板、对话框底、菜单整屏**渲染一次到 Surface 后复用**（暂停菜单是静态的，没必要每帧重画）；
  - 每帧只允许 sprite blit 和文字 render（两者合计 <2ms）。

### Q5. 控制台里的报错可能看不到

- **风险**：脚本在编辑器里跑，traceback 可能一闪而过或只在日志面板；玩家（和评审）只看到窗口卡住。
- **方案**：`main.py` 顶层包一层 try/except，捕获后把 traceback 的**最后 6 行直接画到屏幕上**，而不是静默退出。

### Q6. 工作目录不一定是项目目录

- **方案**：所有路径由 `config.BASE_DIR`（基于 `__file__`）拼接，**已实现**。新增文件一律走 `config.*_DIR`，不要写相对路径。

### 附：`BLEND_RGBA_MULT` 有 ±1 定点误差

SDL 用 `(d*s)>>8` 而不是 `/255`，白色（255）乘完是 **254**。做颜色断言（比如自检脚本）时要留 ±2 容差，别用 `==`。

## 4. Python 3.6 语言层禁用清单

| 禁用 | 原因 | 替代 |
|---|---|---|
| `x := expr` | 3.8+ | 先赋值再用 |
| `f"{x=}"` | 3.8+ | `"x=%r" % x` |
| `dataclasses` | 3.7+ 标准库（本机靠 backport） | 普通类 + `__init__` |
| `from __future__ import annotations` | 3.7+ | 字符串注解或直接不写 |
| `subprocess.run(capture_output=True)` | 3.7+ | `stdout=subprocess.PIPE` |
| `math.dist` / `math.prod` | 3.8+ | `compat.dist` / 手写循环 |
| `typing.Literal` / `Protocol` | 3.8+ | 不用类型约束 |
| `dict1 \| dict2` | 3.9+ | `d = dict(a); d.update(b)` |
| `list[int]` 泛型下标 | 3.9+ | `typing.List[int]` 或省略 |
| `str.removeprefix` | 3.9+ | `s[len(p):] if s.startswith(p) else s` |

> 以上前 4 项已写成自动扫描规则，`tools/envcheck.py` 每次运行都会检查根目录的 `.py`。

## 5. 三条硬规则

| 规则 | 内容 | 落点 | 违反后果 |
|---|---|---|---|
| R1 | 创建窗口只能调 `compat.make_display()` | `main.py` | 8 位表面，画面全废 |
| R2 | 画圆角/裁剪/距离只能调 `compat.*` | `ui.py`、`world.py` | 立即 `TypeError` / `AttributeError` |
| R3 | 读写文本只能调 `io_utils.*` | `world.py`、`save.py` | 加载中文关卡直接崩 |

R1–R3 由 `tools/envcheck.py` 的静态扫描兜底（扫描 `border_radius`、`.clipline(`、`math.dist(` 等字面量）。

## 6. 体检脚本

```bash
python tools/envcheck.py      # 在项目根目录执行
```

覆盖 18 项：运行时版本、32 位显示面、圆角四边闭合、`clip_line` 三组用例、`dist`、`tint`、UTF-8 往返（并反证裸 `open()` 确实会崩）、JSON 往返、音频设备、29 个音效加载、95 张图片加载、中文字体非空像素、禁用 API 扫描、3.8+ 语法扫描、40 精灵帧耗时、面板开销。

全部 PASS 退出码 0，有 FAIL 退出码 1。**每个里程碑结束前跑一次**，出现 FAIL 不要继续往下写。
